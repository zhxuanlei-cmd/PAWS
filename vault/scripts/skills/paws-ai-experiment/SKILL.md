# PAWS AI 实验

让一次实验回答明确的问题，并留下可复算的证据。先读根与项目 `AGENTS.md`、项目 `spec.md`，检索 `decisions/` 中已否决的方案；具体指标、时间粒度、数据合同与晋级要求以项目正本为准，不套用其他客户的数值。

## 运行前确定比较协议

沿用项目已有的实验位置与命名，创建 `type: experiment`、`draft: auto` 的记录，写明 `exp_id`、假设、要支持的决定、负责人及状态。记录至少覆盖：

- **输入与代码**：代码版本及 WIP 边界；数据标识、`data_version`、提取区间、过滤条件与特征来源。
- **信息时点**：区分数据所属时间、发布时间与实际可得时间。预测任务写明起报时点、提前期、训练标签截止及输入历史版本；不能证明当时可得的修订终值、实测或后报数据，只用于明确标注的事后分析或上界实验。
- **划分与比较**：训练、验证、测试的分割规则；基线、候选配置、主指标及必要的约束指标；预先定义比较与决策准则。项目已有通过阈值时冻结阈值；没有阈值也可严谨比较，不自行编造通过线。
- **复算条件**：准确运行命令、配置、环境与工件位置。随机种子、依赖锁、硬件型号按其对结果的影响记录或固定；不适用、不可控制或无法锁定的因素及其影响明确注明。

关键协议无法预先确定时标为探索性实验。观察结果后新增的假设、调参或切片另行标明；反复使用的测试集已参与选择，不能继续宣称独立验证。

## 执行与核验

1. 在**同一可用信息集、同一测试窗口和评测口径**下重跑基线与候选；保留适合任务的简单基线。比较模型时，其他条件尽量一致；比较新增数据时固定共同预测时点，明确输入差异，用消融区分数据与模型的贡献。无法对齐的结果分列，不合成排名。
2. 先做能检验假设的最小实验。检查训练/验证/测试边界、预处理拟合范围、特征与标签可得时间及目标污染；预测回测必须随起报时点移动数据截止，不得把未来实测当作当时预报。关键无泄漏检查失败时停止用该结果作有效比较，保留失败证据。
3. 自产指标由留存的原始输出、测量记录和所需评测输入（如真值/标签）经脚本计算，能追溯到代码、输入、配置和运行；保留数值对账，禁止手工拼出指标或用图形观感替代计算。检查聚合、单位、缺失与排除样本的处理是否符合协议。
4. 保存实际配置、原始结果和日志，记录失败、超时、警告、人工干预及计划偏离；负结果和无效实验同样保留。按任务检查分布变化、随机波动及资源/延迟代价，给出与样本相称的不确定性说明，不挑有利窗口或删去困难样本美化结果。
5. 若修改生产代码，运行受影响的测试及代表性推理或集成路径；实验指标与软件验证结果分别记录。

## 结论与交付

在实验记录中追加结果，保留 `hypothesis`、`config`、`metrics`、`conclusion`、`data_version` 等项目约定字段，并链接实际代码、数据版本、运行命令、环境和结果工件；对需固定身份的工件记录哈希。

- 比较表注明对象/品种、指标定义与聚合口径、时间粒度、测试区间、有效样本数及排除规则；预测准确率另注明起报方式、提前期与输入信息时点。只覆盖部分站点、季节或起报场景时，结论限定于实测范围。
- 按预定准则给出“支持 / 否决 / 证据不足 / 无效”，说明偏离与局限；否定仅限本次实测形式。无通过阈值时报告相对表现与取舍，不宣称达标。
- 区分**经验效果**与**因果机理**：提升可以被实验支持，原因仍可能未知；没有控制比较或足够证据时写“原因待验证”，不把合理解释写成已证实因果。
- 给出下一步及晋级建议。历史回测、影子运行与生产验收分别依项目 `spec.md` 判断；回测胜出不等于已上线、已通过生产验收或可承诺生产准确率。

## 执行边界

通用真实性要求遵循根 `AGENTS.md`。本 Skill 不扩大工具、写入或外发权限；保留 WIP，不自动 commit/push，不把凭据值写入记录、日志或命令。普通实验记录属于当前任务；不会触发 start/checkpoint/inbox/reflect/harvest/archive 六个手动工作流。
