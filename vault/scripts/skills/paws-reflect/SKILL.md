# 记忆整固

把用户明确表达的长期要求与已确认经验转成可追溯、适用范围清楚的共享记忆。
只输入 `/reflect` 即默认整理当前会话中可见的用户要求、纠正和已确认经验，结合现有 profile 与最近相关记录查重；
不要求用户每次补充固定提示词。用户指定主题、时间范围或来源时，以其指定范围为准。
当前会话没有新增内容时，再按最近 reflect 记录定位有变化的已保存材料；没有新增结果允许零产出。
只按实际可见内容提取，不为此扫描所有宿主私有会话；上下文已经压缩或缺失时说明范围，不声称完整回溯。
仅按本次用户触发执行，不按周、数量或文件年龄自动触发，不连带运行其他工作流。

## 准备

使用安装时设置的 `VAULT_DIR` 或用户明确指定的 vault 路径。无法确定时先核对当前文件和项目所在的 PAWS vault，再继续。
先读根 AGENTS、现有 `memory/profile.md`，
再按本次内容读取相关 `memory/facts/`、episodes、已有项目 worklog 与 `memory/agent/cases/`/candidates。
项目是否建档、当前目录是否在 vault 内、是否已有 Git 仓均不是整固的前置条件；未建档时跳过不存在的
spec/HANDOFF/worklog，不要求先建档或先 checkpoint，也不自动建项目、初始化 Git 或修改当前项目文件。
共享要求仍保存到 vault；实际写入以宿主能访问该目录为前提，入口或写入受限时说明具体阻塞，不把建档当作替代授权。
核对当前同步与 WIP；不自动 pull 或解冲突。存在 WIP/未同步时，只依据可读的本地材料整理并注明边界。
不要把宿主内置记忆目录、私有会话、缓存当作本命令的写域。

## 按证据整固

1. **重复**：核对主体、时间、条件和含义；同义事实保留完整来源，追加关联或在获授权的字段中标注
   `superseded_by`。不删除、不压缩原始 worklog/episodes，不用摘要替代来源。
2. **冲突**：先判断是否仅适用条件或时间范围不同。真实更新需有证据证明旧事实已失效；
   日期较新本身不能决定真伪。无法裁定时并列记录冲突与需要补充的证据，不自动选一个赢家。
   过旧只表示需要复查，除非来源有明确有效期，不把年龄直接等同失效。
3. **稳定偏好**：profile 只保留用户明确表达、适用范围清楚且最终仍有效的要求。合并同义表达，
   纳入用户的后续纠正，不把助手建议或用户未确认的推断写成用户要求。明确声明长期适用的要求一次表达即可保存，
   不要求多个项目重复出现，也不重复询问。保留来源、适用场景和例外；一次性约束留在来源项目/会话中，
   不因用户触发 reflect 就泛化。范围不清或推测出的偏好列为候选。已有 AGENTS/专业 Skill 正本承载的规范只引用，
   不在 profile 复制另一份全文；需要修改这些正式规范时列出具体修订候选，不借整固自动发布。
   有实质变化时维护当前有效 profile，保留 created 和来源；无变化不重写。
   批量撤销现有条目时先列明依据和实际影响；新推断保留 `draft: true`。
4. **可复用做法**：重复出现可作为候选信号，不能仅凭次数认定通用。核对触发条件、输入输出、
   已验证效果、失败反例、成本与适用边界，再判断是知识卡、个人约定还是可执行 Skill。
   不把普通通用常识包装成 Skill；先检索现有 Skill，优先提出其修订候选，避免同义重复；本命令不直接修改正式 Skill。
5. **跨项目洞察**：仅保留能说明条件、证据和反例的可迁移断言，允许零产出，无固定数量指标。

## 写入与审阅

- 来源包含 inbox、literature 或外部剪藏的候选不晋升 fact/insight/skill，不靠改标签绕过来源限制。
- 新知识断言与候选记录使用 `draft: true` 和 evidence 链接，按各对象既有路径与 schema 写入；
  profile 维护现有单一文件，fact 使用 memory/facts，wiki/insight 才应用对应的扁平目录、受控分类与真实双链规则。
  检索同义卡与历史反例后再建卡；新卡判定、去 draft 由用户确认。
- Skill 的 `draft: true` 与 evidence 写在 `memory/agent/candidates/<id>.md` 候选记录；
  `memory/agent/candidates/<id>/skill/SKILL.md` 按运行时 schema 编写，不混入 draft 等候选记录字段。若本次明确要求发布，再依
  [Skill 审阅与注册](references/skill-publication.md) 准备审阅包并等待内容绑定的批准。
  执行 /reflect 本身不代表批准候选上线。
- 只使用当前角色允许的写域；可用时运行 fm_lint/MOC 或固定维护检查，回读变更与来源。

## 完成结果

说明合并/保留/冲突/候选各项及证据、实际文件变更和未决问题。有新增处理结果时，在
`memory/episodes/YYYY-MM-DD.md` 追加 `## reflect` 小节，简记主题/来源范围、变更与未决项；新文件使用 episode schema、`draft: auto`。
当前会话的新要求在该小节保留必要原话或准确摘录及可用的来源定位，profile 引用此记录；无需取得私有会话 ID。
未建档来源也使用这一记录路径，项目归属未知时留空，注明实际来源目录（若有），不伪造项目 slug 或创建平行要求库。
没有新增结果时不写记录。必需写入失败时报告“部分完成”和剩余动作；不执行 commit/push 或其他工作流。
