| 项目 | 要求与确认依据 |
|---|---|
| 目标平台与运行时 | 由 agent 核对交付操作系统、架构、语言/工具版本及必要硬件约束；未确定项注明原因，不照抄本机版本 |
| 环境定义入口 | <项目环境定义> |
| 依赖与隔离 | 优先沿用项目原生声明和锁文件；项目环境可重建，本机环境名称/绝对路径只作设备绑定，不是项目合同 |
| 安装、运行与验证 | 由 agent 填写可执行入口及所需资源；在隔离目录验证按锁恢复、最小运行和项目验收，证据写 worklog/HANDOFF |
| 外部服务 | 待确认；凭据只引用凭据索引，不记录值 |

完整依赖清单只在代码仓维护，本节引用相对路径和用途；锁文件存在不等于恢复已验证。建档探测只列常见入口，不读取其正文或执行安装；嵌套 workspace、其他语言及非标准命名由 agent 按任务继续核对。

选型顺序：已有工具链优先；新普通 Python 项目默认考虑 `pyproject.toml` + `uv.lock` + 项目 `.venv`，有明确原生库/跨语言依赖时选择 Pixi 或适用的 Conda 项目定义；Node 项目沿用原生包管理器与锁文件；系统级依赖确有需要时再用 Dev Container。纯材料项目只记录制作工具与验收平台，不创建无用途的代码环境。

恢复命令应校验声明与锁的一致性，如 `uv sync --locked`、`pixi install --locked` 或 npm 项目的 `npm ci`；运行、IDE/LSP 与测试使用同一项目定义。具体 Python、工具与平台版本由实际依赖确定，不生成猜测版本或手写伪锁文件。现有共享环境不随建档升级、降级或迁移；后续在已授权开发范围内建立隔离环境并验证。
