# PAWS 项目整理与固化

把一个探索期堆积、通常尚未入库的代码仓，收敛为可迭代、可部署、可交接的工程形态。
整理不是结项：它把项目推进到可迭代状态，`/archive` 才处理结束，二者不互相替代。

## 前置

用户明确发起整理，即认为项目达到阶段性稳定。先确认实际 checkout 和整理范围，读根与项目 `AGENTS.md`、项目主页及 `spec.md`，并核对 `decisions/` 中相关的已否决方案。未完成待办照实记录；已经成立的阶段性整理授权不取决于全部业务验收通过。

## 正本认定与保留

目录名称或最近会话叙述只能提供线索。用现有交付物、验收证据和可复算指纹确认正本。

1. **复算交付指纹。** 对交付记录中声明的大小和 SHA-256 重新计算。记录匹配与断链结果，并通过清单或构建记录追溯产出该交付物的代码和配置。
2. **交叉核对版本。** 比较指纹与源码版本、交付时间和验收记录。相互冲突时列出冲突项，由用户裁定；命名中出现 `final` 或 `delivery` 只能作为检索线索。
3. **保留未确证对象。** 对无法关联成功交付、仍生效决定或验收材料的脚本与目录单列清单。无法确认是否仍有用途时保留可恢复副本。
4. **先移动再复现。** 经核对后可把应降级的对象整体放入 `attic/` 或约定的保留位置。复现通过并获得明确删除授权后才删除。

## 阶段 0 · 现场快照

修改前先在仓库外留可恢复的独立快照，覆盖本次涉及的跟踪和未跟踪文件。支持写时复制的文件系统可用写时复制工具；其他环境可用独立文件副本。确认快照可读，记录位置、版本和覆盖范围。大体积工件与私有资料按现有存储和保留约定处理，Git 暂存与提交须由用户授权。

## 阶段 1 · 正本台账

由交付物反查台账，至少记录交付物路径、字节数、实算 SHA-256、验收证据、正本源码路径和核心依赖。把未核实映射列为断链，在整理结束前记录每项的裁决或保留位置。

## 阶段 2 · 分类落位（只移不删）

正本代码进包目录；一次性探针、非最终变体、断链项一律进 `attic/`；
大体积数据与中间产物移出仓库或写入 `.gitignore`；实验记录与验收证据保留（证据链）；
文档归项目 vault 或 `docs/`。

## 阶段 3 · 工程化补齐

核对依赖环境、路径和数据去向，再补齐运行入口。

- **依赖与环境**。写清运行环境的取得方式与版本约束。环境若跨项目共享，按既有 ADR 保护它，
  记录约束而不是往仓里塞清单去覆盖；交付包自带的 `requirements.txt` 属于交付物，不等于开发环境清单。
- **绝对路径**。扫描待入库文件中的本机绝对路径，改为可配置项。
- **数据与产物取舍**。`data/`、`artifacts/`、`outputs/` 逐个定去向（入库 / 忽略 / 外置），不留"待裁决"。

再补运行入口（一条命令跑通）、数据合同与部署说明，并与 `spec.md` 对齐。

## 阶段 4 · 复现验证（完成条件，不是可选项）

在整理后的仓里从零跑通，复现台账中已交付的关键数字，容差事先写明。
跑不通或数字对不上即为删多了或漏了依赖：从阶段 0 快照取回，不在残缺状态上打补丁。
测试与门禁按项目既有要求执行，通过、失败与未执行分别记录。
通过后才可征求用户确认删除 `attic/`。

## 阶段 5 · 才动 Git 与跨会话交接

先核对 `.gitignore`、当前 Git 状态和预计提交范围。区分源码、必要工件、私有材料以及本机生成物。已有明确的本地暂存与提交授权后，按确认范围执行并记录提交；未授权时提供待提交清单。

将正本台账放进仓内，例如 `docs/正本台账.md`。台账保存交付物指纹、验收证据、正本路径、降级清单与断链裁决。已登记项目的 `HANDOFF` 指向台账，按已确认的工程入口更新 `spec` 和 `tasks`。
用实际 checkout 分别运行 `./scripts/repo_snapshot.sh --project <slug> --cwd <实际 checkout>` 和
`./scripts/handoff_sync.sh --project <slug> --cwd <实际 checkout>`，再回读派生状态。

## 完成条件与边界

正本台账在仓内可打开且每条指纹经实测复算；断链项已有用户裁决；复现验证通过并有记录；
`.gitignore` 覆盖应忽略产物；已授权并完成的提交只含确认的内容；已登记项目的 HANDOFF 指向台账；快照仍可用于恢复。
任一项未达成，报告"整理未完成"与具体缺项，不把整理计划称作已整理。

不 push、不动共享环境、不删快照、不改 vault 历史日志、凭据只留索引、不触发六个手动工作流；
整理不改变模型晋级、验收结论或任何既有业务裁定。
