# 项目结项归档

把一个明确项目结束为可回顾、可检索、可恢复的档案。输入为项目名/路径与归档意图；
默认核对成功完成，用户明确要求终止时按终止归档。仅用户本次触发有效，不自动识别项目“彻底完工”。
此命令管理 vault 项目档案，不归档 Codex/Claude/OpenCode 会话。

## 前置核对

1. 使用安装时设置的 `VAULT_DIR` 或用户明确指定的 vault 路径。无法确定时先核对当前文件和项目所在的 PAWS vault，再继续。
   读根/项目 AGENTS，用 `scripts/paws_repository.py`
   的 `--vault <vault> --cwd <实际目录>` 确定项目和 checkout，并与用户指定项目核对。
   `--project` 只查询默认仓库，不能识别当前 worktree；有歧义先确认，不批量归档其他项目。
   用户已明确项目且档案存在、但现场目录不可用时，用 `--project <slug>` 查询默认目录状态并读取现有档案，
   报告“已登记，现场不可用”；无法完成所需交付/WIP 核对时列具体缺项并保持原状态，不误报未登记或已归档。
2. 读取主页的业务目标/预期交付、spec、HANDOFF、tasks、相关 ADR、最终交付物和验收证据，现场核对 Git/WIP。
   按 spec 的真实验收条件逐项列出完成/未完成/未验证及证据，区分代码、文档、数据、模型等交付形态。
   `completed` 须满足 spec 的有效验收条件，不额外要求客户验收、上线或发布；若 spec 确有这些要求，
   不能用测试通过替代。`terminated` 核对用户明确的终止意图、已做范围与未完成项，不要求未做交付存在或验收通过。
   两种结果中声称已完成的事项都须有证据，不能从会话口头结论推定。
3. 整理剩余任务、已知缺陷、外部依赖和维护责任。未完成项必须有明确去向：留作限制、
   用户取消、用户接受不做，或已存在的承接项目/任务；不能直接全部勾选完成。
   明确取消用 `[-]` 并保留去向/理由，只有有证据完成才用 `[x]`。
4. 有 WIP 时说明实际文件、所属工作、保留位置及跨设备可恢复性；无须为了归档强制清空 Git，
   但归属/处置未明确的工作不能默默封存。成功归档存在验收缺口，或任一归档的遗留事项未定时，
   先交付具体差距清单并保持现有项目状态；明确终止按终止结果记录，不标为成功交付。

## 写结项档案

条件满足后，归档调用本身授权本节的逻辑归档，不重复确认同一决定。

- 先核对主页 `closure_record` 与已有相关结项记录。同一次归档重试沿用原记录路径和已记录日期，
  补齐缺失写入/派生/检查；日志只追加新增或更正内容，不重复既有结项段落，不仅凭某个文件已 archived 就提前返回。
- 在 `worklog/YYYY-MM-DD-closure.md` 追加结项记录（记录类 frontmatter、`draft: auto`），写明
  归档结果 completed/terminated、目标与实际结果、交付清单/版本/路径、验收证据、遗留事项去向、
  关键决定索引、恢复所需环境/依赖/数据与凭据索引。敏感值不进入记录。
  知识萃取只记录已完成成果或“尚未执行”；不调用 harvest，不为归档复制一套知识卡。
- 维护主页的最终有效项目介绍、交付入口及限制；在主页 frontmatter 设置 `status: archived`、
  `closed_on: YYYY-MM-DD`、`closure_outcome: completed|terminated`、`closure_record: worklog/<实际文件名>`。
  这些结项事实以主页为唯一正本。spec 只维护最终开发/验收要求与限制、对齐 status，保留 created 和历史决定。
- HANDOFF 保留最终交接状态、现场 WIP 与恢复入口，status 设 archived；next_action 指向恢复条件，
  不再列为待开发任务。tasks 保留真实勾选及遗留说明，status 设 archived；主页继续聚合状态与历史正本。
  不删除工作日志、决策、未完成任务；不重命名项目，不移动到 `40-archive/`，不改双链目标。
- 全部判断/任务写完后，以 vault 为工作目录依次运行
  `./scripts/handoff_sync.sh --project <slug> --cwd <实际 checkout>`、
  `./scripts/repo_snapshot.sh --project <slug> --cwd <实际 checkout>`，再回读状态与链接。
  已满足下方完成条件且没有新增变化时返回现有结项记录，避免重复写入。

## 完成条件

成功归档确认所需交付存在且验收通过；终止归档确认终止理由与未完成范围清楚，不要求未交付物存在。
两者都确认已声称交付/验收的结果有对应证据、遗留事项有明确说明、spec/HANDOFF/tasks/主页状态一致，
结项记录可打开，凭据只存索引，原始 WIP 保留；运行可用的 fm_lint/MOC 检查并报告实际结果。
失败或缺权限时报告“归档未完成/部分写入”和具体文件，不把准备好的清单称为已归档。

输出归档结果、结项记录、交付入口、剩余限制及恢复方式。归档不等于已同步至其他设备；
不执行 Git 写操作、发布、压缩打包、目录移动、服务关闭、凭据撤销或其他 PAWS 命令。
以后恢复维护由用户明确提出，届时先核对最新现场，再更新状态并记录恢复原因。
